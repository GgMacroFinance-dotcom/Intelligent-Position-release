# 协调员不再自己追加核验、不再把核对数据派给运维测试（2026-11-15）

> 真实模型（协调员 `gpt-6-astra`，研究员和运维测试 `gpt-6-luna`）+ 真实数据（本机 `macro-mcp`，FRED 经 WhichAPI）。对应[发布前清单](../../release-checklist.md)的 R-26。
> 环境：Claude 云端开发容器，没有 bubblewrap，`sandbox.mode: none`。一共跑了 18 遍，约 1.80 美元，其中协调员约 1.69 美元。

## 问题

[2026-11-11 的验收](../../acceptance-2026-11-11.md)记了两个没修的问题：

- **协调员过度核验。** 研究员交回结果后，协调员不肯直接汇总，追加一轮核验任务，要“官方新闻稿和发布日期”这类工具取不到的材料。
- **协调员把核验数据的任务派给了运维测试岗位。**

这次先在当时的 `main`（`ad240a8`）上复现，两个问题都还在，见下面“结果”里“改之前”一栏。

## 改了什么

`rust/ip.example.yaml` 里协调员的岗位说明，补了三处：

1. **岗位边界**：取数、核对数字、写研报都是宏观研究员的事；运维测试只管服务器、数据管道、代码和测试，不要把核对数据的任务派给它。
2. **交回来的是什么**：任务结果是一段结论摘要加报告路径；报告全文在执行员工的工作目录里，协调员读不到，也不用读，按摘要汇总并附上报告路径。
3. **工具取到的数据就是已核验的来源**：提需求的人没要求复核时，不要自己追加核对任务或发卡片，也不要要求官方新闻稿、发布日期这类工具取不到的材料；交回的结果里写了“未取得”的，照实写进汇总，不要再派人去补。

第 2 处是复现时才看出来的原因：示例配置里协调员没有文件工具（`tools: false`），读不到研究员写的报告。有一遍它在追加的任务里写的就是“当前对话无法读取报告，且摘要缺少逐项来源与日期，尚不能作为可交付材料”。

## 怎么验证

每遍起一个全新数据目录的 `ip serve`，用 [`drive.mjs`](drive.mjs) 经 `/ws` 把问题直接发给协调员 `coord-1`，选择卡片自动选推荐项，25 秒没有新动静算结束。脚本记下每一轮、每次工具调用、每个任务和每张卡片。

三个问题：

| 问题 | 原文 | 用意 |
| --- | --- | --- |
| 例会材料 | 下周一投资例会要一页材料：美国最近一个月的通胀和利率怎么走，资金面紧不紧 | 2026-11-11 验收用的原题 |
| 例会材料，带一项取不到的数据 | 下周一投资例会要一页材料：美国最近一个月的通胀、利率和高收益债信用利差怎么走 | ICE BofA 的高收益债利差 `macro-mcp` 不提供，研究员只能写“未取得”，看协调员会不会追着补 |
| 要求找人核对 | 把美国最新一期 CPI 同比和 10 年期美债收益率取出来，找人核对无误后给我一句话结论 | 人明确要求核对时，看核对派给谁 |

配置是 `rust/ip.example.yaml` 改四处：沙箱改成 `none`；取消 `mcp_servers.macro.env_from` 的注释；`env_inherit` 加上容器的代理变量；协调员的每日预算从 10 美元调到 0.8 美元，防止某一遍失控（没有哪一遍用到上限，最多的一遍协调员花了 0.29 美元）。“改之前”用 `ad240a8` 的示例配置，“改之后”用这个 PR 的。

## 结果

| | 改之前（10 遍） | 改之后（8 遍） |
| --- | --- | --- |
| 协调员追加派活的遍数 | 4 | 0 |
| 有任务派给运维测试的遍数 | 3 | 0 |
| 发了选择卡片的遍数 | 1 | 0 |
| 最后的汇总里带“待核验”“补核”“未独立复核”这类说法的遍数 | 5 | 0 |
| 平均每遍花费（美元） | 0.119 | 0.076 |

按问题分：

| 问题 | 改之前 | 改之后 |
| --- | --- | --- |
| 例会材料 | 5 遍：1 遍追加了“补齐正文及关键数据核验”的任务，花费翻倍（0.19 美元）；3 遍的汇总带核验类说法 | 3 遍：都只派一次活，汇总不带核验类说法 |
| 例会材料，带一项取不到的数据 | 3 遍：1 遍追加了 3 个任务（其中 1 个派给运维测试）、发了 1 张卡片，这一遍花了 0.32 美元；2 遍的汇总带核验类说法 | 3 遍：都只派一次活，汇总里写明利差“未取得”，没有追着补 |
| 要求找人核对 | 2 遍：都另开了一个“独立核对”的任务，派给运维测试 | 2 遍：取数和核对合成一个任务，派给研究员；花费从约 0.08 降到约 0.045 美元 |

每一遍的数字在 [`runs.json`](runs.json)。

## 看到的

- **最糟的一遍把验收里的三件事都重演了。** “带一项取不到的数据”改之前的第 2 遍：研究员交回后，协调员追加任务要求“核对 BLS、BEA 实际发布记录”，研究员做不到，把任务标为受阻；协调员再派运维测试去“排查数据访问受阻”；然后发卡片问人怎么办。协调员一共跑了 6 轮。
- **改之后协调员照实转述缺口。** 比如汇总里写“高收益债利差数据未取得，无法判断走阔或收窄”，并给出报告路径。人明确要求核对的那个问题，汇总里写的是“已做交叉核对，但收益率对照数据的日期及口径不同，尚不能宣称完全核验无误”。
- **样本小。** 10 遍对 8 遍，方向是清楚的，但不能当成比例的精确估计。改之前出问题的也只是一部分：例会材料 5 遍里 4 遍没有追加派活。

## 顺带发现：沙箱关着时，员工会自己上网取数

改之前有 3 遍运维测试被派去核对数据，它都用 shell 里的 `curl` 直接访问外部网站（BLS、BEA、财政部、FRED 的 `fredgraph.csv`），其中一遍取到了 ICE BofA 的高收益债利差，协调员随后让研究员也走同一条路。这两样正是 `macro-mcp` 特意不做的：不抓 FRED 的图表 CSV、不提供 ICE 的序列（见[开源前的核对](../../macro-mcp-open-source.md)第 3、6 节）。

能这样做，是因为这个容器没有 bubblewrap，沙箱是关着的。默认配置（`sandbox.mode: bubblewrap`、`network: false`）下 shell 命令不能联网；这一点这次没有验，CI 里有对应的自动测试。把沙箱关掉或者打开 `sandbox.network` 的部署，数据工具的这些限制对员工不起作用。

## 文件

- [`drive.mjs`](drive.mjs)：经 `/ws` 发一条消息、等整件事结束、把过程汇总成 JSON 的脚本，要 Node.js 22。评测命令 `ip eval` 只等被测员工的一轮结束，测不了“协调员派活 → 执行 → 交回 → 汇总”这种跨员工的流程，所以另写了这个。
- [`runs.json`](runs.json)：18 遍各自的任务、卡片、汇总里的核验类说法、联网的 shell 命令次数和花费。完整的对话记录没有放进仓库。
