## 这份文档怎么用

## 定位与目标

intelligent-position（I.P.）的首要目标是做一个有影响力的开源项目：一套“AI 原生组织架构”，由社区共建。以下都是已定。

- 主推的是整套架构，智能岗位是证明生产力的样板。
- 现在只用宏观研报一个岗位做展示，其余岗位依次铺开。第二个岗位是“运维、测试”。
- 岗位按通用岗位设计，不限于写代码。
- 商业化是顺带的：驻场服务和云主机托管。海外云主机服务是帮客户配置他们自己的 GPT、Claude 账号。
- 代码全部 Apache-2.0。nightly-lab 是非商用许可，只参考设计，不复制代码。
- 70/20/5/5 是上下文的设计理念，不是量化机制。
- 人的注意力放在一处：自动路由先给方案，人类决策者修改确认。

## 整体架构

一个 Rust 进程跑在云 Linux 主机上，每个数字员工是进程里的一个异步任务，不是一个独立的命令行进程。

| 层 | 做什么 | 现在用什么 | 以后 |
| --- | --- | --- | --- |
| 协调层 | 接收请求、派活、汇总 | 云端最强模型 | 不变 |
| 执行层 | 各岗位员工取数、写报告、干活 | 便宜的云端模型 | 换成岗位专家小模型，只需换端点 |
| 路由 | 决定请求交给哪个岗位 | 规则，匹配不到就出决策卡给人 | 人改过的决定沉淀成新规则，人批准后生效 |
| 工具与数据 | 沙箱里的工具、MCP 服务器、公开数据 | 本机和远程 MCP 都支持 | 需要浏览器的岗位先配 Playwright MCP |
| 渠道与外部引擎 | Slack 线程、Codex | Slack 在真实工作区的公开频道里走通过一次（2026-11-16，经本机转发器连接）；Codex 用真实的跑通过一次示例项目（2026-11-14） | Claude Code 引擎接口已留，未实现 |

harness 从第一天就用 Rust 写，目的是充分利用硬件效率。代码在仓库 `rust/` 下，13 个 crate，约 2.6 万行（含测试，2026-11-15）。性能算功能的一部分，新增热路径要带 `ip bench` 基准。

## 模型与接口

真实运行用 OpenAI 的两个模型，接口走 OpenAI 现行的 Responses 方式。都是已定。

| 角色 | 模型 | 每日预算 |
| --- | --- | --- |
| 协调员 | `gpt-6-astra` | 10 美元 |
| 宏观研究员 | `gpt-6-luna` | 2 美元 |
| 运维测试员 | `gpt-6-luna` | 未设 |

- 第一次真实调用发现：这两个模型在旧的 chat completions 格式里不能带工具。解决办法是给模型客户端加 Responses 接口，已加（PR #31）。
- 旧格式保留，给其他厂商和以后的本地小模型用。每个端点在配置里写明用哪一种。
- 不换模型，不走第三方转接网关。
- 配置里的模型价格 2026-11-14 按 OpenAI 的模型文档核对过，补了缓存命中和缓存写入的价格（PR #54）。用之前请再核对。
- 密钥只放环境变量或云端环境的密钥设置，不进仓库、PR 和聊天。

## 数据

宏观岗位直接调 Finance Macro Data API 取美国和全球数据，中国数据也要加进这个 API。

- Finance Macro Data API 就是 which-api 仓库里的 `packages/macro-mcp`，一个 MCP 服务器，原有 12 个工具。数据来自纽约联储、FRED、美国财政部、TIC、Federal Register、SEC。已定。开源版放在本仓库的 `macro-mcp/`，现在 13 个工具（9 个美国、4 个中国国家统计局），FRED 经 WhichAPI 托管服务取（维护者 2026-11-13 定，见 backlog C-2）。
- 测试部署在 Render 免费套餐上，闲置会休眠，休眠后第一次连接约等 1 分钟。
- 中国数据：2026-11-15 加了国家统计局 4 个工具（搜指标、浏览目录、取数、CPI/PPI/PMI/M2 快捷入口），托管版见 which-api PR #14，开源版 `macro-mcp` 同步；`ip data pull` 不再拉统计局数据。境内网络真实跑通，境外网络能否访问没验（backlog E-2、A-2）。
- 已验证的范围：2026-11-11 的真实验收经 Render 上的测试部署取到了真实 FRED 数据；2026-11-14 起用本机启动的 `macro-mcp` 经 WhichAPI 托管服务取 FRED，配真实模型跑过评测（backlog A-1、C-2）。

FRED 数据只留 Finance Macro Data API 这一个来源，`examples/public-data` 里重复的 FRED 序列删掉。已定。

## 路线与先后

先后已定：验证，评测，开源准备，上下文与记忆，然后是第二个岗位，小模型测试放在最后。真实跑通之前不加新功能。

1. **先验证。** 宏观岗位用真实模型和真实数据跑通：研究员取数，协调员派活，研究员写报告，协调员汇总，记录每一步的结果、花费和报错。这一项 2026-11-11 通过（美国数据），Codex 真实验收 2026-11-14 通过，Slack 真实验收 2026-11-16 通过（Slack 链路；见验收记录里没验的部分）。还有两项要人动手：境内网络核对统计局指标代码、一位工程师在自己的主机上照验收手册跑一遍。
2. **质量评测。** 这一版只做两个固定的宏观问题，当冒烟测试用。检查用程序判定：报告里的数字都能在工具结果里找到，数字带观测日期，取不到的写“未取得”而不是估算，报告结构齐全。两个问题能发现明显退步，不足以比较两个模型谁更好。
3. **开源发布准备。** 见下一节。
4. **上下文机制和员工记忆。** 设计见 `context-memory-design.md`，参考开源 Codex（Apache-2.0）的记忆架构，分 7 步做。已定：记忆按岗位存、同一岗位内共享；默认值 2026-11-13 定的是关，2026-11-16 改成开。七步都已做：人写的两层内容会进提示词，后台会从结束的对话里提炼摘要，再按岗位合并成记忆摘要放进提示词。员工能用工具查本岗位的记忆，人在对话里要求“记住”“忘掉”时会记成更正。控制台有“记忆”页，人可以看、改、抹掉、清空，也可以按对话关掉记忆。第 7 步 2026-11-15 用真实模型跑了一遍，整条流程按设计工作，见 `memory-2026-11-15-real-run.md`；维护者 2026-11-16 定默认开。
5. **第二个岗位“运维、测试”。** 用真实 Codex 跑通了示例项目 `examples/ops-demo`，还没在真实项目上跑过。
6. **专家小模型测试。** 这是为以后接入做准备，这一版不训练。只挑几个已经后训练好的现成模型，换端点接进来，用评测集测一遍。测哪几个模型、跑在哪里还待定，所以放在最后开发。

现在不做：新渠道（飞书、邮件）、更多岗位、小模型训练。桌面端和手机端 App 维护者 2026-11-16 定了现在就做，2026-11-21 定各平台 App 用 Flutter 开发，见 `apps-plan.md` 第 9 节和 backlog F。

## 协作与合并规则

两位工程师不按人分块，他们各自的 Claude 直接推进未完成的部分，工程师之间线下沟通。都是已定。

- 开工前先看仓库的未完成事项清单和开放的 PR，同一条不做两遍。
- 一个 PR 只做一件事，尽量小。
- 动到敏感路径的 PR，要一位工程师读过代码再合并。其他 PR 本地检查通过后直接合并。
- 做完一条，在同一个 PR 里更新清单和 README 的勾选项。
- 没在真实环境跑过的东西，不写“已上线”“已验证”。

| 敏感路径 | 位置 |
| --- | --- |
| 工具与沙箱 | `crates/ip-tools/` |
| 令牌与鉴权 | `ip-server` 的 `ws.rs`、`mcp.rs`，`ip-runtime` 的 `gateway.rs`，`app.rs` 和 `config.rs` 里涉及密钥的部分 |
| MCP | `crates/ip-mcp/` |
| 渠道 | `crates/ip-connectors/`，`ip-server` 的 `channels.rs` |
| 外部引擎 | `crates/ip-engines/`，`ip-runtime` 的 `engine.rs` |
