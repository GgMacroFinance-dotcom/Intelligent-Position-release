## 定位（2026-11-09 与用户确认）

- **开源项目是主体**：做一个有影响力的开源项目，推出一套全新的 AI 原生组织架构，邀请社区共建。FPDE 驻场和云主机托管只是顺道的商业化，用来展示这套架构的真实生产力。主 CTA 是 GitHub，商业合作降为次要入口。
- **架构是主角**：首屏讲 AI 原生组织架构，紧跟五层架构与范式对比。
- **核心分工**：调度协调的 Bot 用云端最顶尖的模型；执行的 Bot 现阶段也调用云端模型（快速档）。执行层预留专家小模型接口，以后换成后训练的 1B 左右专家模型（约 3.6G 显存）（2026-11-09 更新：执行层现阶段先调用云端模型，1B 专家模型作为预留的后续方向）。
- **人类注意力点**：自动路由先给出一套方案，人类决策者修改、确认。
- **Rust**：整个 harness 用 Rust 重写，充分利用硬件效率。
- **70/20/5/5** 对外称"设计理念"，不写成精确配比。
- **只展示一个岗位**：宏观研报智能岗位（验收中：还没用真实模型和真实数据跑通，跑通后再写“已上线”）。其余五个岗位（运维、测试，网络安全，债券承做，数据分析，美国税务）放进路线图，弱化展示。

未定项，页面上统一显示"待定"：怎么连公司 Database；接哪些外部 API（只确认 Finance Macro Data API）；每台主机 ?核 ?G GPU 存储。

## 2. 五层架构

- 标题：**五层架构：把一个岗位重新设计成 AI 原生单元**
- 副标题：传统公司里，人按部门分工，AI 只是工具。在 I.P. 架构里，岗位本身是 AI 原生的：协调 Bot 负责调度，执行 Bot 负责干活，人类决策者只在关键节点修改方案。

| | 传统 Agent | I.P. 岗位架构 |
| --- | --- | --- |
| 组织方式 | 人按部门分工，AI 是工具 | 岗位是 AI 原生单元，人是决策者 |
| 交付单元 | 一次对话 / 一个 Agent | 一个岗位：职责、规范、电脑、记忆 |
| 上下文 | 临时写的 prompt | 70/20/5/5 设计理念 + 规章约束 |
| 算力 | 一个模型包打天下 | 协调与执行分两层，都调用云端模型；执行层预留专家小模型 |
| 运行环境 | 共享环境 | 1 岗 1 台云 Linux 主机 |
| 人的角色 | 全程盯着对话 | 自动路由先给方案，人类决策者修改 |

五层（左侧可点选，右侧显示说明、开源项目里有什么、商业化服务、待定问题）：

| 层 | 名称 | 说明要点 |
| --- | --- | --- |
| L5 | 岗位（先从宏观研报开始） | 架构是主体，岗位是产出；先只做宏观研报 |
| L4 | 人类决策者与多端协同 | 自动路由出方案，人类决策者修改；桌面 + 手机 App |
| L3 | Rust harness 与云 Linux 主机 | 整个 harness 用 Rust 重写；1 岗 1 机；3 项待定 |
| L2 | 协调 Bot + 执行 Bot | 协调用云端顶尖模型；执行现阶段调用云端快速档模型，预留 1B 专家 |
| L1 | 岗位定义与上下文治理 | 70/20/5/5 设计理念、团队 Context、权限分层 |

### 4b. 推荐模型配置决策器（演示区第三个 Tab）

给智能岗位里不同的 Bot 推荐模型和 effort。规则在 `homepage/decider.js`（纯函数，可单独测试），换厂商或型号只改文件顶部的模型表。

输入：模型厂商（Claude / OpenAI GPT / Google Gemini / DeepSeek / 自动：每档选最便宜）、Bot 角色（协调 / 执行）、任务类型（规划、写作、工具调用、摘要、数据拉取与计算、格式化）、数据敏感度（公开 / 内部 / 涉密）、调用量、时延、质量要求。输出：模型、effort、每条规则的理由、警告、每千次调用的成本、更省 / 更稳的备选。

| 规则 | 做法 |
| --- | --- |
| 厂商与档位 | 每个厂商有 4 档阶梯（小 / 中 / 强 / 最强），规则先算出档位，再映射到该厂商的型号；对比基准是同厂商第 3 档 |
| 协调 Bot | 起点第 3 档（Claude 为 Opus 5.5；GPT 为 5.1 Sol；Gemini 为 3.1 Pro 预览；DeepSeek 为 V4 Pro），effort high（架构的核心分工：协调用云端最顶尖的模型） |
| 执行 Bot 起点 | 数据拉取、格式化 → Haiku 5.5 low；摘要、写作 → Sonnet 5.5 medium；工具调用 → Sonnet 5.5 high；规划 → Opus 5.5 high |
| 质量「错了代价很高」 | 升一档模型，effort 加一级（最高到 Fable 5.1） |
| 质量「高」 | 模型不变，effort 加一级 |
| 执行 Bot 且调用量高、质量一般 | 降一档模型 |
| 需要即时响应 | effort 降一级 |
| 内部数据 | 警告：确认走客户自有的企业 / Team 账号或 API，并关闭训练用途 |
| 涉密数据不出内网 | 标"需要确认"：现阶段都是云端模型，不满足，先脱敏或等 1B 本地专家；由人类决策者拍板 |

**数据说明**：已接入 Claude、OpenAI（gpt-6 系列）、Google（Gemini 3.x）、DeepSeek；档位是按价格和命名推断的，没做过评测；Gemini 价格页更新于 2026-06；DeepSeek 价格来自第三方汇总，需复核；Kimi / Qwen / GLM / MiniMax 暂未接入（只查到第三方价格，没有确切的 API 型号）。

页面下半部分按这套规则自动生成"宏观研报岗位各 Bot 的推荐配置表"（协调、数据拉取、指标计算、政策摘要、图表排版），点一行可载入左侧表单。成本用假设的 token 量估算（协调 8K 入 / 2K 出，执行 3K 入 / 0.5K 出），标"示意"。

## 5. 底座

标题：**为什么这套架构能跑出真实生产力**

| 大字 | 标题 | 正文 |
| --- | --- | --- |
| `2 层` | 协调与执行分层 | 协调 Bot 用云端最顶尖的模型做规划和判断；执行 Bot 现阶段调用云端模型。执行层预留了专家小模型接口，以后可以换成后训练的 1B 模型。 |
