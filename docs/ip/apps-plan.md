## 1. 现状：App 能直接用上的东西

下面是读代码核对过的（2026-11-16 的 `main`）。

| 现有部分 | 位置 | 对 App 意味着什么 |
| --- | --- | --- |
| 一个 WebSocket 接口 `/ws`，请求和回复按 `id` 配对，运行时事件推给所有连接 | `ip-server/src/ws.rs`、`protocol.rs` | App 不需要新的业务接口，控制台能做的 App 都能做。请求类型有 26 种：对话、岗位、任务、审批、路由规则、定时任务、记忆、花费 |
| 协议的 TypeScript 类型由 Rust 自动生成（ts-rs） | `rust/web/src/types/` | 各端共用同一份类型，协议改了编译期就能发现 |
| Web 控制台，6 页（对话、岗位与员工、任务、审批、路由规则、记忆），原生 JS 加 JSDoc 类型检查，没有构建步骤，编译进可执行文件 | `rust/web/`、`ip-server/src/console.rs` | App 的界面直接复用这份代码，不重写 |
| 手机布局（F-1）和可安装成应用（F-2，PWA） | `rust/web/` | 手机和电脑已经能把控制台装成应用 |
| 断线自动重连（500 毫秒起翻倍，最多 8 秒） | `web/src/client.js` | 手机切后台再回来能自己连上 |
| 访问令牌：一个共用令牌，配在 `auth_token_env`，用 `Authorization: Bearer` 或 `?token=` 传 | `ws.rs` | 能用，但不适合发给多台设备，见第 4 节 |
| 来源检查：浏览器发来的握手，`Origin` 要和 `Host` 同源或在 `allowed_origins` 里 | `ip-server/src/origin.rs` | 桌面壳的内嵌网页来源是 `tauri://localhost`、`http://tauri.localhost`，要加进白名单 |
| 部署文档已经写了“放在带 HTTPS 的反向代理后面” | `deploy-docker.md` | App 连用户自己的云主机，走这条路就行 |

还缺的：

- **没有按设备区分的令牌和权限**。丢了一台手机，只能换掉共用令牌，所有设备一起重新登录；每台设备都能改路由规则、清空记忆。
- **事件不能补发**。`/ws` 断开期间的事件就丢了，控制台靠重新拉列表补上。
- **没有推送**。人不在 App 前时，新审批卡、员工提问、一轮失败都没人知道，只有 Slack 渠道能提醒。
- **看不到报告**。员工把报告写进自己工作目录的 `reports/*.md`，控制台读不到全文，只能看到交回时的摘要。
- **Markdown 原样显示**。消息里的表格显示成一堆竖线。
- **谁在操作说不清**。发消息、批审批的署名是自己填的名字，不是账号也不是设备。

## 2. 参考了什么

维护者让参考两个项目的手机端和桌面端（2026-11-16 读的设计文档）：

- **openbot（nightly-labs/openbot，即 nightly-lab）**：PolyForm Noncommercial 许可，只读了它公开的设计文档（`docs/architecture/channels-and-messaging.md`、`docs/self-hosted-server.md`、`apps/mobile/DESIGN.md`、`remote/README.md`），没看也没用它的代码。
- **OpenMausBot**：Apache-2.0，读了 `docs/ios-companion.md`、`docs/desktop-companion.md`、`docs/phone-web-app.md`、`docs/notification-and-proactivity-qa.md` 和 `companion/README.md`。代码按许可可以带署名复用，但我们的服务端是 Rust，基本用不上。

| 问题 | openbot 的做法 | OpenMausBot 的做法 | 我们怎么做 |
| --- | --- | --- | --- |
| 技术栈 | 手机 React Native（Expo），桌面 Electron，桌面和网页共用一套界面组件 | 手机原生 Swift，桌面 Electron；桌面“客户端模式”用自带界面连别的主机；另有可安装的网页版 | 网页控制台是唯一的一套界面；先做 PWA，桌面用 Tauri 2 包同一套界面，手机商店版以后再定 |
| 连接 | 主机不开端口，经项目方运营的信令服务和 TURN 中继建 WebRTC | 一个挡在 harness 前面的伴随进程；推荐项目方提供的 HTTPS 隧道或 Tailscale，局域网明文要用户明确选 | 用户自己的 HTTPS 反向代理，或 Tailscale；不运营中继 |
| 配对 | 主机上运行命令出二维码，一次性，2 分钟有效 | 二维码，扫不了时用 6 位数字码，2 分钟一次性；手机上先确认电脑名 | 二维码加 6 位数字码，2 分钟一次性，手机上先确认主机名 |
| 设备令牌 | 账号体系 | 每台设备一个令牌，只存哈希，可吊销 | 每台设备一个令牌，只存哈希，可吊销 |
| 设备能做什么 | 按成员角色 | 默认全部拒绝，按接口逐个放行；电脑控制要单独授权 | 默认“日常”权限，“管理”权限要单独给 |
| 断线 | 按资源刷新 | 事件带游标，重连时补发，补不上就重新拉最新一页 | 事件带序号，重连时补发，补不上就重新拉 |
| 推送 | 项目方运营一个薄中转，持有 APNs/FCM 证书；内容在主机上用和手机共享的密钥加密，中转只见密文 | 只有 App 开着时有提醒；关掉后的推送“要项目方的 APNs 证书和中转”，没做 | 先用 Web Push（主机直接发，协议本身端到端加密）；商店版以后用 openbot 那种只见密文的中转 |
| 推送规则 | 一轮结束、出错、等人输入或审批；“全部”或“只推需要我的”；按岗位、静音、关预览；人在电脑前或 App 在前台时不推；别处处理过的撤掉 | 等人审批或提问、需要人接手、有结果的完成、定时任务失败；每条通知带员工和对话，点开直达那条对话；窗口在前台时不弹 | 两边合起来，见第 5 节 |
| 消息显示 | 渲染 Markdown | 渲染 Markdown，表格在气泡里横向滚动 | 渲染 Markdown，不执行 HTML |

不照搬的：openbot 的 WebRTC 中继和账号体系（项目方要长期运营一整套服务）、OpenMausBot 的托管 HTTPS 隧道（同理），以及两边的语音、电脑远程控制、灵动岛，这些以后再看。

## 4. 连接、配对和权限

### 4.1 网络

App 只连用户自己的主机，项目方不经手业务数据。

| 方式 | 做法 | 适合 |
| --- | --- | --- |
| 公网 HTTPS（默认） | 反向代理（Caddy 或 nginx）加域名证书，见 `deploy-docker.md` | 团队成员分散、要在外网用 |
| Tailscale | 主机和设备进同一个 tailnet，用 MagicDNS 名字（`*.ts.net`）连；流量在 WireGuard 里，`http://` 也是加密的 | 不想把控制台放在公网 |

App 连非本机地址时只接受 `https://` 和 `*.ts.net`，局域网 IP 的明文连接要用户自己勾选“我信任这个网络”。

### 4.2 配对

1. 在主机上运行 `ip device pair --name 张三的手机`，或者在控制台“设备”页点“添加设备”。屏幕上出一个二维码和一个 6 位数字码，2 分钟内有效，只能用一次。二维码里是主机地址和配对码，不含长期令牌。
2. 手机或电脑打开控制台（或桌面 App）的“连接主机”，扫码或输入地址加 6 位码。先显示主机名请人确认，再换取**这台设备专属的令牌**。
3. 服务端只存令牌的 SHA-256、设备名、权限、配对时间和最后在线时间。控制台“设备”页可以改名、改权限、吊销；吊销后这台设备的连接立即断开。
4. 原来的共用令牌保留，等同“管理”权限，给本机浏览器和脚本用。

### 4.3 设备权限

| 权限 | 能做什么 | 默认 |
| --- | --- | --- |
| 日常 | 对话（发消息、看历史、搜索）、审批和员工提问、任务（看、新建、改状态）、看报告、看岗位和花费、自己的推送设置 | 新配对的设备都是这一档 |
| 管理 | 另外能改路由规则、规则草案、定时任务（立即运行）、记忆（改、抹掉、清空）、设备管理 | 要在“设备”页单独给 |

服务端按请求类型逐条放行，新加的请求类型默认只给“管理”，要明确列进“日常”才放开（学 OpenMausBot 的默认拒绝）。“日常”另外能读两样东西：有没有路由规则（新对话默认自动分派要用）、哪些对话关了记忆（对话页顶上的提示要用），只读不能改。清单见 `m2-spec.md` D-31。

### 4.4 署名

用设备令牌连上的请求，署名一律用设备名，忽略请求里自填的 `author`。共用令牌连上的仍用自填名字。

## 5. 推送

### 5.1 什么时候通知

服务端统一决定，网页、PWA、桌面 App 都照这一份规则：

| 事件 | 级别 | 说明 |
| --- | --- | --- |
| 新审批卡、员工提问 | 需要我 | 点开直达那张卡或那条对话 |
| 一轮失败、定时任务失败 | 需要我 | 标题写员工名，正文写一句原因 |
| 一轮完成且有回复 | 全部 | 正文是回复的头一两句，去掉表格、代码块，密钥打码 |
| 任务完成交回 | 全部 | 正文是交回的结论摘要 |

每台设备自己设：级别（“只推需要我的”默认 /“全部”/ 关）、按岗位关掉、静音到某个时间、要不要预览文字。

### 5.2 不重复打扰

- 这台设备的控制台开着、页面在前台时不发推送，页面自己用浏览器通知或界面提示。
- 同一个人在别的设备上 30 秒内有操作时不推（各端定时报一次“有人在用”）。
- 审批卡或提问在一处处理过之后，别的设备上那条通知自动撤掉（用同一个通知标签覆盖）。

### 5.3 怎么送达

- **第一版用 Web Push。** 主机生成自己的 VAPID 密钥，PWA 和浏览器订阅后，主机按 Web Push 协议（RFC 8291 加密）直接发给浏览器厂商的推送服务。推送服务只见密文，项目方不运营任何服务。iPhone 要先“添加到主屏幕”（iOS 16.4 起）。
- **以后的商店版**用 openbot 那种中转：主机用和手机配对时约定的密钥加密，中转只转发密文给 APNs/FCM，不存不记。到时单独设计。
- **桌面 App** 用系统通知，托盘图标上显示待办数。

## 8. 安全要点

- App 只信任配对过的那一台主机，证书校验不能关。
- 令牌不写进日志和地址栏；桌面 App 放系统钥匙串，网页放浏览器存储（和现在一样）。
- 桌面壳的内嵌网页不加载远程脚本，原生接口按 Tauri 的权限声明只开通知、钥匙串、托盘、开机启动。
- 手机丢了：在“设备”页吊销，服务端立即断开它的连接。
- 推送正文不放数据和报告内容，只放标题和一两句预览，预览可以关。
