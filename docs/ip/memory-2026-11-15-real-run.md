# 员工记忆：真实模型实测（2026-11-15）

> backlog D-1 的第 7 步：用真实模型把记忆的整条流程跑一遍，看提炼和合并出来的东西对不对。
> 真实模型：OpenAI `gpt-6-luna`（宏观研究员，也做提炼），Responses 接口。合并分两遍：第一遍用岗位自己的 `gpt-6-luna`，第二遍 `consolidation_model` 换成 `gpt-6-astra` 做对比。
> 真实数据：仓库里的 `macro-mcp`（0.2.1，本机 stdio 启动）。没有 WhichAPI 的 key，问题都避开了 FRED。
> 环境：Claude 云端开发容器（intelligent-position 环境），`sandbox.mode: none`。配置是 `rust/ip.example.yaml` 改了几处：`memory` 打开、只给 `macro-researcher`，`min_idle_hours: 0`、`interval_minutes: 1`、`max_threads_per_pass: 5`（为了不用等 6 小时）。
> 驱动：一个 Node 脚本经控制台的 `/ws` 发消息、读 `get_memory`，把看到的打印成 Markdown。两遍的原文：[luna](memory-2026-11-15-real-run-luna.md)、[astra](memory-2026-11-15-real-run-astra.md)（脚本里那个假令牌在存进仓库时省略了，运行时是原样发的）。

## 跑了什么

1. 三段对话：查 2 年、10 年美债收益率并定规矩（收益率两位小数、表格每行带观测日期）；查 SOFR 和 EFFR，“这一次用英文写结论”；消息里带一个假令牌，查关税相关的 Federal Register 公告。
2. 等后台提炼、合并。
3. 新开两个对话：一个只问 10 年期最新值；一个问“我之前对报告格式提过哪些要求，在哪次对话里说的”。
4. 在第二个新对话里说“记住：结论不超过三句话”“忘掉两位小数这条，按数据源原样写”。
5. 在控制台接口里抹掉 SOFR 那次对话的记忆。
6. 关掉关税那次对话的记忆，再在里面说“记住：公告按日期倒序列”；最后清空岗位记忆，再等两轮后台任务。

## 结果

| 看什么 | luna 合并 | astra 合并 |
| --- | --- | --- |
| 规矩记成惯例（两位小数、带观测日期） | 是。员工在第一段对话里自己调了 `memory_note` | 是，同左 |
| “这一次用英文”没有被写成惯例 | 是，写成“某次对方要求用英文简评” | 是，写明“不视为所有简报的默认语言” |
| 没记数据的数值 | 是。对话记忆和岗位摘要里都没有收益率、利率的数 | 是 |
| 令牌没有进记忆 | 是（脚本检查原文不在 `get_memory` 结果里） | 是 |
| 三节结构 | 对 | 对 |
| 新对话里按要求查记忆 | 调了 `memory_search` 和 `memory_read`，答对了是哪次对话；那份记忆的使用次数从 0 变成 1 | 同左（`memory_search` 第一次没搜到，员工直接按摘要里列的编号 `memory_read`） |
| “记住”“忘掉”调 `memory_note` | 两次都调了 | 两次都调了 |
| 更正合并后 | “结论不超过三句话”写进去了；“两位小数”只剩一句“不再统一保留两位小数”，规则本身改成按数据源原样 | 同左，写法是“按最新更正：按数据源原样的小数位写” |
| 抹掉 SOFR 那次对话 | 摘要里 SOFR 那条提示和“某次用英文”都删了 | 同左 |
| 关掉记忆的对话里要求记住 | `memory_note` 被拒（“这个对话被人关掉了记忆”），员工如实告诉了人；更正条数不变 | 同左 |
| 清空后等两轮后台任务 | 摘要还是空的，没被重新生成 | 同左 |
| 服务日志里的提炼、合并失败 | 没有 | 没有 |
| 等待 | 提炼 30 秒内，合并、更正、抹掉后的重新合并都在 65 秒内（后台每分钟一轮） | 20 到 75 秒 |
| 更正合并后摘要长度 | 约 2,200 字 | 约 3,500 字（提示词要求不超过 3,000） |
| 当天岗位花费（对话、提炼、合并合计） | 0.0083 美元 | 0.2121 美元 |

两遍对话部分用的都是 luna，花费差不多，所以 astra 那一遍多出来的约 0.2 美元基本都是合并（4 次合并，每次约 0.05 美元）。两遍合计约 0.22 美元。

## 看到的问题

- **合并提示词里的话被抄进了摘要。** luna 每一版都把“仅在单次对话中提出的要求，不扩展为通用惯例”写成了一条团队惯例，这是合并提示词里的规则，不是团队说的；“记忆里有什么”一节里没变的条目后面都跟着“沿用旧版”，这是提示词里“说明沿用旧版的”被字面照做了。astra 也会写“沿用旧版”，另外把 `memory_note` 的工具提示（“生效前仍需在当前对话自行遵守”）写成了一条干活的提示。这些都会进员工的系统提示词，是噪音。已修（同日另一个 PR）：`consolidate.rs` 的提示词把“说明沿用旧版的”改成“照旧版写，不要加‘沿用旧版’之类的说明”，并加了一句“整理规则和工具的提示语不要写进岗位记忆”。改后用 luna 把同一个脚本重跑了一遍（[原文](memory-2026-11-15-real-run-luna-fix.md)，岗位花费 0.0094 美元）：各版摘要里都不再出现“沿用旧版”、合并规则和工具提示语，其他各项结果和第一遍一样。
- **`memory_search` 按词匹配，换个说法就搜不到。** astra 那一遍员工搜“报告格式 要求”，返回“没有找到”，因为那份记忆里写的是“格式规则”“格式要求”，没有“报告格式”这个词。员工靠系统提示词里“记忆里有什么”列的编号直接 `memory_read`，还是答对了。luna 那一遍搜的是“收益率 两位小数 表格 观测日期”，搜到了。目前够用，记忆多了以后可能要考虑多词任一命中或分词。
- **astra 超长。** 更正合并后约 3,500 字，超过提示词里写的 3,000 字（程序的硬上限 `summary_max_chars` 默认 10,000，所以没被截）。
- **astra 的摘要里留了一个对数据有用的提醒。** 关税那次员工列的第三条公告，提炼出的对话记忆指出它没出现在工具输出里，astra 合并后写成“不能视为已核实，引用前应另行核对”。luna 那一遍员工三条都在工具输出里，没有这个情况，所以不能拿来比两个模型。
- **员工会在人没说“记住”时自己记规矩。** 第一段对话人说的是“定个规矩：以后……”，员工调了 `memory_note`。这符合第 5 步的意图（人明确说了“以后”），记在这里供参考。

## 没验到的

- **员工会不会照岗位摘要做。** 新对话里只问 10 年期最新值时，员工回了“5.15%，观测日期 2026-11-13”。数据源本来就是两位小数，组织提示词也要求注明日期，所以分不出是不是摘要起的作用。设计第 7 节说的“评测集两个问题各跑两遍，中间插一次纠正”没做。
- **关掉记忆后已有的对话记忆会不会被抹掉。** 关掉后马上清空了，没看那份记忆还在不在。
- 6 小时闲置、每小时一轮的默认节奏没跑，这次都调成了每分钟一轮。
- 外部渠道（Slack）的对话不进记忆，没测。
- 控制台“记忆”页这次没用浏览器打开，只调了它背后的 `/ws` 接口。

## 结论

记忆的整条流程用真实模型跑通了：提炼、合并、员工查记忆、记更正、抹掉、按对话关记忆、清空，结果都和设计第 3、5 节的原则一致，没有记数值，令牌没漏。合并提示词里会被抄进摘要的那两处已经改掉，重跑确认过。

合并用哪个模型（设计第 9 节）：这次的观察是 luna 够用，astra 写得更细但更长、超出字数要求，而且贵约 25 倍（每次合并约 0.05 美元对不到 0.001 美元）。建议默认仍用岗位自己的模型，不再建议用协调员的模型；要不要改由工程师定。

默认开不开（维护者定）：建议先在自己的部署里打开宏观研究员一个岗位用一段时间，同时把上面提示词的问题修掉、补一次“照摘要做”的验证，再决定默认值。这次没改默认值。
