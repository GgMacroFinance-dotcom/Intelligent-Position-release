# 提示词缓存命中率：真实模型实测（2026-11-14）

> backlog D-2 的第二步：用真实模型跑一遍 `ip eval` 和一次协调员派活，把各岗位的命中率记下来。
> 真实模型：OpenAI `gpt-6-astra`（协调员）、`gpt-6-luna`（宏观研究员），Responses 接口。
> 真实数据：仓库里的 `macro-mcp`（0.2.1，本机 stdio 启动），FRED 经 WhichAPI 托管服务取。
> 环境：Claude 云端开发容器，没有 bubblewrap，`sandbox.mode: none`。配置是 `rust/ip.example.yaml`，改动和[评测记录](evals/2026-11-14-luna/README.md)写的一样。
> 命中率 = 命中缓存的输入 token / 全部输入 token，数字来自 `ip eval` 的输出和 `spend_today`。

## 结果

| 场景 | 岗位 | 输入 token | 其中命中缓存 | 命中率 | 输出 token | 花费（美元） |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| `ip eval` 第 1 遍，两题 | 宏观研究员 | 39,222 | — | 84% | 4,000 | 0.0059 |
| `ip eval` 第 2 遍，两题 | 宏观研究员 | 22,408 | — | 95% | 1,596 | 0.0030 |
| 协调员派活，3 轮 | 协调员 | 3,761 | 1,276 | 34% | 907 | 0.0830 |
| 协调员派活，1 轮 | 宏观研究员 | 70,875 | 62,810 | 89% | 6,110 | 0.0101 |

`ip eval` 只打印命中率，没有单独打印命中的 token 数，所以前两行那一列空着。两题分开看：第 1 遍 70% 和 94%，第 2 遍 97% 和 94%。

协调员派活用的是 2026-11-11 验收时的同一个问题：“下周一投资例会要一页材料：美国最近一个月的通胀和利率怎么走，资金面紧不紧”。经控制台的 `/ws` 发给 `coord-1`。这次协调员没有发选择卡片，也没有追加核验任务：派一次活，研究员交回，协调员汇总，合计 0.093 美元（11-11 那次约 0.57）。交付的一页材料原文在 [prompt-cache-2026-11-14-report.md](prompt-cache-2026-11-14-report.md)。11-11 发现的“通胀率拿不到”这次没有出现：研究员用 `units=pc1` 取到了 CPI、核心 CPI、PCE 的同比。

## 怎么看

- **研究员命中率高，不用改。** 研究员一轮里调很多次工具，每一步的请求都带着前面全部的历史。前缀稳定，命中率在 84% 到 97% 之间。
- **协调员命中率低，是因为请求短，不是因为前缀不稳。** 协调员每次请求只有 1,000 到 2,000 token。第一轮两步共 2,077 token，一个也没命中：按 OpenAI 的说明，提示词达到 1,024 token 才缓存，第一步之前也没有可命中的前缀。第二轮一步 1,684 token，命中 1,276（76%），说明系统提示词和工具定义这段前缀是稳定的。
- **协调员的钱主要花在输出上。** 按配置里的价格（astra 输入 10、输出 50 美元/百万 token），这次协调员输入约 0.038 美元，输出约 0.045 美元。命中率就算提到 100%，也只省输入那一部分。
- **配置里没有缓存价。** `prices` 只写了 `input` 和 `output`，没有 `cached_input`，所以账本把命中缓存的 token 也按全价算，记的花费比实际偏高。核对 OpenAI 定价页后，可以给两个模型补上 `cached_input`。（当天已补上，同时发现 OpenAI 另收缓存写入费，账本也一并按它计价，见 backlog D-2。）

结论：目前的命中率没有低到要改代码。backlog 里列的候选改动（给 OpenAI 端点发 `prompt_cache_key`、检查压缩摘要对前缀的影响）先不做。等协调员的对话变长，或者花费变高时，再按同样的办法量一次。

## 顺带发现的

- **研究员会为小歧义发卡片。** `ip eval` 第 2 遍第一题，研究员没取数，先问“最近一周”按 5 个交易日还是 7 个自然日算，所以没通过。见[评测记录](evals/2026-11-14-luna/README.md)。
- **纽约联储的利率接口在这个容器里连不上。** `get_reference_rates`（SOFR、EFFR）要连 `markets.newyorkfed.org`，云端环境的网络白名单里只有 `www.newyorkfed.org`。研究员改从 FRED 取了同样的序列，并在材料里写明了。白名单已经补上这个主机，这次运行没有重跑。
- 研究员第一次调 `update_task` 时漏了 `task_id`，报参数错误，重试后成功。
