# I.P. 开源项目与商业化服务的边界

> 状态：草案 v0.2（2026-11-09），按用户最新定位改写。
> 适用范围：智能岗位（Intelligent Position, I.P.）的代码、模型权重、数据和服务。
> 本文不是法律意见。正式对外开源前，请让律师过一遍第 1 节和第 5 节。

## 0. 定位与规则

**I.P. 首先是一个有影响力的开源项目**：一套全新的 AI 原生组织架构，邀请社区共建。FPDE 驻场和云主机托管是顺道做的商业化，作用是证明这套架构在真实公司里能产生生产力。

由此得出的边界：

| 类别 | 放在哪里 | 许可 |
| --- | --- | --- |
| 代码：整个 Rust harness、Router、上下文组装、桌面与手机端、岗位描述格式、后训练工具 | 公开仓库 | Apache-2.0 |
| 岗位描述文件（宏观研报等） | 公开仓库的岗位库 | Apache-2.0 |
| 开源的专家小模型权重 | 公开发布 | 取决于基座模型许可证（见第 5 节） |
| 客户专属的规范、配置、连接器参数、定制权重 | 客户自己的仓库 | 归客户 |
| FPDE 驻场、云 Linux 主机托管与运维、海外云主机上配置客户自有账号、按岗位定制后训练 | 服务合同 | 商业合作 |

**一句话规则：代码全部开源；商业化只卖服务，不卖闭源模块。** 客户专属的东西作为数据和配置放进客户自己的仓库，不 fork 产品。

> 这条规则后续还会细化（2026-11-09 用户确认"后续会细化"）。如果将来确实需要闭源模块，再单独开一个目录并换许可证，届时需要贡献者协议。

### 1.1 参考 nightly-lab 时要注意什么

借鉴架构思路（模块怎么分、流程怎么走）没有问题，著作权保护的是代码的具体表达。风险只出在"把它的代码逐文件翻译成 Rust"：逐行翻译在法律上仍可能被视为衍生作品，会把 PolyForm 的非商用限制带进来。所以：

1. **按设计文档写，不按源码翻译**。先把要借鉴的架构写成我们自己的设计文档，再按文档写 Rust，不要打开它的源文件对照着写。
2. **登记参考点**。在 `docs/nightly-lab-parity.md` 记下"参考了哪个功能的设计"，方便以后说明来源。
3. **参考副本不进公开仓库**。现在内部分支里的 `nightly-lab/` 和 `third_party/nightly-labs-openbot/` 只做内部阅读。公开仓库对外之前删掉它们，CI 加一个检查确认发布分支里没有这两个目录。

> 建议对外公开的仓库从干净的历史开始（新建仓库，或从 `main` 起一个没有 nightly-lab 提交历史的分支），不要直接把带 nightly-lab 历史的分支设为 public。

## 4. 技术底座：整个 harness 用 Rust 重写

2026-11-09 确认：**整个 harness 用 Rust 重写，充分利用硬件效率**，不是只重写核心，也不是先用 TS 做再迁移。

- **协调与执行的分工**：调度协调的 Bot 调用云端最顶尖的模型；执行的 Bot **现阶段也调用云端模型**（2026-11-09 确认），可以选更快、更便宜的档位。执行层预留专家模型接口，以后换成后训练的 1B 左右专家模型（约 3.6G 显存），部署在岗位自己的云 Linux 主机上。长期按"每个岗位训练自己的专家模型"设计，预计未来 2–3 年会涌现大量这类小模型。
- **人类注意力点**：自动路由先给出一套完整方案，人类决策者修改、确认后执行。
- **前端**：OpenMausBot（React）和 nightly-lab（Electron + SolidJS）两条路线目前都保留作参考，前端最终用哪条路线另行决定；nightly-lab 的前端同样只参考设计，不复制代码。

建议的 Rust workspace：

```
crates/
  ip-spec/            # 岗位描述格式与 JSON Schema
  ip-context/         # 上下文组装（70/20/5/5 设计理念）
  ip-router/          # 协调 / 执行分工、自动方案、人类修改记录
  ip-runtime/         # 调度、队列、记忆
  ip-sandbox/         # 云 Linux 主机上的隔离与资源管理
  ip-fleet/           # 多主机编排
  ip-harness-sdk/     # 连接器接口
  ip-grab/            # information grab 外部数据采集
  ip-expert/          # 专家小模型运行器（llama.cpp / candle 等，许可证逐个核对）
  ip-train/           # 后训练工具与评测
apps/desktop/  apps/mobile/
positions/macro-research/
```

## 5. 模型权重与数据的许可证

1. **1B 基座模型**：能不能开源分发、能不能商用，取决于基座模型的许可证（Llama、Qwen、Gemma 条款各不相同）。选定基座前先核对，只发布许可证允许再分发的权重。
2. **后训练数据**：用云端大模型合成训练数据前，确认该服务商条款是否允许"用输出训练模型"。客户数据训练出的权重，合同里写清归属。
3. **JD 数据**：招聘网站的服务条款可能禁止抓取。开源采集器只提供框架和遵守 robots.txt 的示例源。

## 6. 商业化服务的注意事项

1. **海外云主机账号配置**：账号归客户、费用由客户直接付给模型厂商，我们只做部署和运维，对外不写"聚合订阅"或"Token 中转"。个人订阅通常只限本人使用，团队场景建议客户用 Team / Enterprise 套餐或 API。
2. **"3.6G 显存满血运行"** 需要可复现的基准测试后再对外宣传。
